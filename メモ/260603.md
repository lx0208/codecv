
# DGX Spark QSFP / RoCE 直結ネットワークの切断・設定ロールバック手順

2台のDGX Spark間でQSFPケーブルにより直結しているRoCEネットワーク設定を削除し、安全にQSFPケーブルを取り外します。

本手順は、**両方のDGX Sparkノード**で実施してください。

1. 事前確認

まず、RoCE / QSFP ネットワークを使用している分散処理、コンテナ、ジョブが停止していることを確認します。

```
docker ps
```

念のため、稼働中の Docker コンテナをすべて停止します
```
docker stop $(docker ps -q)
```

2. 現在のネットワーク設定を確認

現在のインターフェース名と IP アドレスを確認します。

```
ip -br addr
ip route
```

例：

```
enp15f0np0    UP    192.168.100.10/24

```

もう一方のノードでは、以下のような IP が設定されている場合があります。

```
enp15f0np0    UP    192.168.100.11/24

```
enp15f0np0 は環境によって異なる場合があります。実際に表示された QSFP / RoCE 用インターフェース名を確認してください。

3. Netplan 設定ファイルの確認

以下のコマンドで、RoCE 用の netplan 設定ファイルが存在するか確認します。

```
ls -l /etc/netplan/

```

以下のようなファイルが存在する場合、netplan により RoCE 用 IP が設定されています。

```
/etc/netplan/40-cx7.yaml

```

念のため、設定内容も確認します。
```
cat /etc/netplan/40-cx7.yaml
```

4. Netplan 設定のバックアップ

```
sudo cp /etc/netplan/40-cx7.yaml ~/40-cx7.yaml.bak
```

5. RoCE / QSFP ネットワーク設定の削除

RoCE 用の netplan 設定ファイルを削除します、その後、netplan 設定を反映します。

```
sudo rm /etc/netplan/40-cx7.yaml
sudo netplan apply
```


6. 設定削除後の確認

以下のコマンドで、RoCE 用 IP アドレスが削除されていることを確認します。

```
ip -br addr
ip route
```

192.168.100.10/24 または 192.168.100.11/24 など、QSFP 直結用に設定した IP アドレスが表示されていなければ、設定削除は完了です。

7. IP アドレスが残っている場合

もし `ip -br addr `に RoCE 用 IP がまだ表示される場合は、手動で削除します。

Dgx Spark 1 の例：

```
sudo ip addr del 192.168.100.10/24 dev enp15f0np0

```

Dgx Spark 2 の例：

```
sudo ip addr del 192.168.100.11/24 dev enp15f0np0

```

enp15f0np0 は実際のインターフェース名に置き換えてください。

削除後、再度確認します。

```
ip -br addr
```

9. QSFP ケーブルの取り外し

設定削除後、QSFP ケーブルを取り外します。

取り外し時の注意点：

- ケーブル本体を強く引っ張らないでください。
- QSFP コネクタのプルタブ、またはリングタブを持ってください。
- ポートに対してまっすぐ水平に引き抜いてください。
- 抜けにくい場合は無理に引っ張らず、コネクタのロックが解除されているか確認してください。


10. 最終確認

QSFP ケーブル取り外し後、通常の管理ネットワークや SSH 接続に問題がないことを確認します。

```
ip -br addr
```

以上で、DGX Spark 間の QSFP / RoCE 直結ネットワーク設定のロールバックおよびケーブル取り外し作業は完了です。
